Verdict on the base method. nvfp4 with plain defaults is the safe precision on every model. int4 trails it by 1.4 to 4 dB at any rank or smoothing setting. The remaining defects are int4 trajectory drift and temporal flicker on video, both of which live in activation quantization and are not fixed by any recipe setting. Two follow-up sections below set this recipe beside calibrated checkpoints and present the Hadamard rotation that addresses the int4 gap.

Rank and smoothing

The data-free recipe has two settings: rank, the size of the low-rank branch that keeps the largest weight components in 16-bit, and smoothing strength, how far each input channel is rescaled before 4-bit rounding, from 0 (off) to 1 (fully flattened). The defaults are rank 32 and smoothing 0.5.

  • Up to +2.7 dB, but only at the right smoothing. Rank 128 reaches 15.99 dB at smoothing 0.25 and gains nothing at the default 0.5. The best smoothing value falls as rank grows, because the low-rank branch and smoothing absorb the same outliers.
  • Cost. Transformer memory grows about 16% from rank 32 to 128. Inference time and quantize-on-load time do not change.
  • Not worth it with rotation. Hadamard rotation at rank 32 reaches the same quality (15.42 dB) at the default memory, and rank 128 with rotation is worse (14.28 dB). See the Hadamard section.
  • Other models. On MiniMax-H3, rank 64 cuts weight error by only about 3%; no end-to-end comparison was scored. Qwen-Image-2.1 and FLUX.2 were run at rank 32 only.

Per-layer error

  • Calibration trades weight precision for activation precision. Its smoothing scales are much larger, so the weights themselves are rounded less exactly: 12.2% vs 8.2% relative weight error (nvfp4) and 12.6% vs 9.8% (int4) on LTX. In exchange, activation error drops sharply.
  • The full layer comes out ahead. Scored on 512 real activation rows per layer through the whole 4-bit path, calibrated error is lower on 946 of 1344 layers (nvfp4): 6.9% vs 7.6% (nvfp4) and 9.3% vs 11.4% (int4).
  • And far more even. Data-free error is spiky, reaching 80% activation error on some attention output layers. Calibration brings those to 20% or less, including the layer with the largest weight error (6.2% vs 9.7% full error).
  • Caveat: the activations came from a data-free nvfp4 run because a bf16 capture did not fit on that machine, so the comparison is fair between the two recipes but absolute levels depend on that run.

Hadamard rotation: the int4 improvement

Everything above uses the stock recipe. This section is the one change that moved int4 by more than trajectory noise: a data-free blockwise Hadamard rotation of the quantized residual, with the matching Walsh–Hadamard transform fused into the activation-quantization kernel. Design

The problem it solves. 4-bit quantization gives each group of 64 input channels one shared scale. If one channel in a group carries a value ten times larger than its neighbours, the scale has to stretch to fit it, and every other channel in that group is rounded on a coarse grid. Diffusion transformers have exactly this: a handful of activation channels are consistently much larger than the rest, in a different place for every token. The low-rank branch of SVDQuant[1] absorbs the largest weight outliers, and smoothing[2] moves some activation range into the weights. But smoothing scales are computed from the weights, so they cannot follow outliers that change from token to token, and those remain the main error source.

The idea: rotate before rounding. Multiplying a vector by an orthonormal matrix changes its coordinates but not its length, and multiplying both sides of a matrix product by the same rotation leaves the result unchanged. A Hadamard matrix is a particularly convenient rotation: every entry is ±1/√n, so each output coordinate is an even mix of all inputs. One large channel gets spread across the whole block, and the rotated values look close to Gaussian, which a uniform 4-bit grid represents far better. This "incoherence processing" was introduced for weight quantization by QuIP[3] with random orthogonal matrices. QuIP#[4] switched to randomized Hadamard transforms because they can be applied fast. QuaRot[5] extended it to activations to run LLMs fully in 4 bits, and SpinQuant[6] learns the rotation instead of fixing it.

The math, step by step.

  1. A linear layer maps an input vector to an output vector:

    \[ y = W x, \qquad W \in \mathbb{R}^{m \times n},\; x \in \mathbb{R}^{n} \]

  2. Smoothing moves range from the activations into the weights with one scale per input channel. The product is unchanged:

    \[ y = \underbrace{\big(W\,\mathrm{diag}(s)\big)}_{\hat W}\;\underbrace{\big(\mathrm{diag}(s)^{-1} x\big)}_{\hat x} \]

  3. SVDQuant splits the smoothed weight into a rank-32 part, kept in 16-bit, and a residual \(R\):

    \[ \hat W = L_2 L_1 + R, \qquad L_1 \in \mathbb{R}^{32 \times n}\ \text{(LoRA down)},\quad L_2 \in \mathbb{R}^{m \times 32}\ \text{(LoRA up)} \]

  4. Only the residual path is quantized, both its weights and its activations, to 4 bits:

    \[ y \approx \underbrace{L_2\,(L_1 \hat x)}_{\text{16-bit LoRA}} \;+\; \underbrace{Q(R)\;Q(\hat x)}_{\text{W4A4 GEMM}} \]

  5. Insert an orthonormal matrix \(H\) (so \(H H^\top = I\)) between the residual and its input. This is exact:

    \[ R\,\hat x \;=\; R\,H H^\top \hat x \;=\; (R H)\,(H^\top \hat x) \]

  6. Now quantize the rotated operands instead. \(Q(RH)\) is computed once at load time, and \(H^\top \hat x\) per token inside the kernel; a Hadamard matrix is symmetric, so \(H^\top = H\):

    \[ y \approx L_2\,(L_1 \hat x) \;+\; Q(R H)\;Q(H \hat x) \]

  7. \(H\) is block-diagonal, one \(64 \times 64\) Hadamard block per 4-bit quantization group, so every group keeps its own scale. Each block is applied with a fast Walsh–Hadamard transform in \(\log_2 64 = 6\) add/subtract stages:

    \[ H = \mathrm{diag}\big(H_{64}, \dots, H_{64}\big), \qquad H_{64} = \tfrac{1}{8} \begin{bmatrix} 1 & 1 \\ 1 & -1 \end{bmatrix}^{\otimes 6} \]

How it is applied here.

  • Weights, at load time. The residual is rotated before rounding, as Q(R · H). H is block-diagonal with one 64×64 Hadamard block per quantization group, so each group's scale still covers only its own 64 channels. H is a fixed matrix, so no data is needed and the method stays data-free.
  • Activations, at run time. The matching rotation is applied to each token inside the kernel that quantizes activations, as a fast Walsh–Hadamard transform in registers (64 inputs in log₂64 = 6 add/subtract stages). It runs after the smoothing division and after the low-rank projection, so the low-rank branch still sees the original input. This is the same fused online-rotation pattern QuaRot[5] uses for LLMs.
  • Why it beats smoothing here. Smoothing has to choose one scale per channel ahead of time. The rotation needs no statistics: it spreads whatever outlier a token has at run time, which is what per-token outliers require.

Why it does not help nvfp4. nvfp4 already gives every 16 channels their own fine-grained scale, and its 4-bit floating-point grid is built for heavy-tailed values. A 64-wide rotation mixes four of those small groups together and removes the tails the format handles well. Egiazarian et al.[7] show that nvfp4's small groups neutralize classic outlier treatments, and they use smaller block-wise rotations tuned to the format instead. That matches the −2.2 dB measured here.

Rules learned

  • int4 only. On nvfp4 it costs 2.2 dB and doubles flicker. The kernel option is validated for int4 and must stay off for nvfp4.
  • Rank 32, smoothing off. Rotation and rank do not stack (r128 + H64 is 1.1 dB below r32 + H64), and smoothing on top of rotation lowers activation SNR. Recommended config: rank=32, hadamard=True, smooth_exponent=0.
  • Pre-Blackwell hardware reaches nvfp4-class quality. A100 int4 + H64 (15.64) ≈ RTX nvfp4 (15.87) on MiniMax, at the same runtime as plain int4. On Qwen-Image-2.1 rotated int4 ties nvfp4 at CFG off (22.8 vs 22.7) and sits 0.8 dB below it under CFG, within 0.04 LPIPS.
  • It removes most of int4's CFG sensitivity on Qwen. Plain int4 lost 3.5 dB from CFG off to CFG 4; rotated int4 loses 2.6, about what nvfp4 loses. The compositions int4 forked come back.
  • Not a flicker cure. Mean flicker improves; the worst scene does not.
  • Variants already tested with no extra gain: sign-flipped H64, H128. Random permutation is the only untested piece of the OrbitQuant family.

Tested and negative

  • LoftQ alternating SVD/quantize iteration: 4.6 to 11.1% reconstruction gain, below the pre-registered gate.
  • Excluding the 288 worst layers (+3.5 GB, no effect; error is systemic). Decode-timestep dither (does not mask flicker).
  • Activation scales derived from AdaLN modulation weights (helps only cross-modal to_q, hurts attn1).
  • Frame-shared activation scales (+2.5 to 5 pts error, +75% jitter). DCT on all linears (harmful for nvfp4).
  • AdaLN is not an error source on MiniMax (see the calibrated section).

Code samples

Each sample is a complete script: it quantizes the transformer while it loads, with no calibration data, then generates one image. Quantizing takes roughly 5 to 20 minutes depending on model size. The examples use Qwen-Image-2.1; other models work the same way with their own transformer and pipeline classes.

Setup

# Data-free quantize-on-load lives on branch feature/data-free-quantization of rootonchair/diffusers.
# Qwen-Image-2.1 also needs upstream main merged in.
pip install "git+https://github.com/rootonchair/diffusers@feature/data-free-quantization" kernels
export DIFFUSERS_TRUST_REMOTE_KERNELS=true   # loads rootonchair/nunchaku-lite-kernels from the Hub

nvfp4

# nvfp4: Blackwell GPUs only. Best quality, no tuning needed.
import torch
from diffusers import NunchakuLiteQuantizationConfig, QwenImage21Pipeline, QwenImage21Transformer2DModel

model_id = "Qwen/Qwen-Image-2.1"

# Quantize the transformer while it loads. pre_quantized=False means data-free:
# no calibration data, the 4-bit weights are computed from the bf16 checkpoint.
quantization_config = NunchakuLiteQuantizationConfig(
    svdq_w4a4={
        "precision": "nvfp4",
        "group_size": 16,  # fixed for nvfp4
        "rank": 32,        # size of the 16-bit low-rank branch
    },
    pre_quantized=False,
)
transformer = QwenImage21Transformer2DModel.from_pretrained(
    model_id,
    subfolder="transformer",
    quantization_config=quantization_config,
    dtype=torch.bfloat16,
    device_map="cuda",
)

# The rest of the pipeline (text encoder, VAE) stays in bf16.
pipe = QwenImage21Pipeline.from_pretrained(model_id, transformer=transformer, dtype=torch.bfloat16)
pipe.to("cuda")

Changing rank and smoothing

# int4 with a larger rank and retuned smoothing (best LTX int4 setting without rotation: +2.7 dB, +16% memory).
import torch
from diffusers import NunchakuLiteQuantizationConfig, QwenImage21Pipeline, QwenImage21Transformer2DModel

model_id = "Qwen/Qwen-Image-2.1"

# Quantize the transformer while it loads. pre_quantized=False means data-free:
# no calibration data, the 4-bit weights are computed from the bf16 checkpoint.
quantization_config = NunchakuLiteQuantizationConfig(
    svdq_w4a4={
        "precision": "int4",
        "group_size": 64,
        "rank": 128,              # default 32; larger = more memory, same speed
        "smooth_exponent": 0.25,  # default 0.5; 0 = off, 1 = fully flattened
    },
    pre_quantized=False,
)
transformer = QwenImage21Transformer2DModel.from_pretrained(
    model_id,
    subfolder="transformer",
    quantization_config=quantization_config,
    dtype=torch.bfloat16,
    device_map="cuda",
)

# The rest of the pipeline (text encoder, VAE) stays in bf16.
pipe = QwenImage21Pipeline.from_pretrained(model_id, transformer=transformer, dtype=torch.bfloat16)
pipe.to("cuda")

image = pipe(
    prompt="A street musician playing saxophone under a lamppost, holding a cardboard sign that says OPEN MIC, warm evening light.",
    num_inference_steps=40,
    generator=torch.Generator("cuda").manual_seed(42),
).images[0]
image.save("qwen_int4_rank128.png")
  • group_size is fixed by precision: 16 for nvfp4, 64 for int4. Any other value is rejected.
  • rank is required. smooth_exponent (0 to 1, default 0.5) and hadamard are optional and apply only when pre_quantized=False.
  • At rank 32, smoothing makes no measurable difference, so "smooth_exponent": 0.0 or leaving it out are equivalent in quality.
  • Quantized layers are chosen automatically. To keep specific layers in bf16, pass exclude_targets=[...] to the config.
