The same 4-bit SVDQuant checkpoints that run on CUDA now run on an M5 Mac, through PyTorch MPS (Diffusers) and MLX (mflux). New Metal kernels run the 4-bit layers as int8 matrix multiplies on the GPU's Neural Accelerators. Measured on an M5 with 24 GB, at 1024².

Two runtimes

Nunchaku Lite loads Nunchaku SVDQuant checkpoints into existing pipelines instead of shipping its own. On a Mac there are two pipeline ecosystems, so there are two runtimes.

Both read the same checkpoints, including the lite-infer repos with a runtime manifest and older lite checkpoints that list their quantized layers in config.json.

How the 4-bit layers run on M5

An SVDQuant layer splits each weight into a small low-rank branch kept in 16-bit and a 4-bit residual with one scale per 64 input channels. On CUDA, the residual runs as a 4-bit × 4-bit matmul. Apple GPUs have no 4-bit matmul, but the M5's Neural Accelerators run int8 matmuls, reachable from Metal 4 shaders.

  • Activations are smoothed and quantized to int8 per token, a finer grid than the 4-bit activations the CUDA kernel uses.
  • Weights keep their 4-bit values. Each per-group scale is split into a per-channel scale and an integer-domain multiplier, so the int32 accumulator can run over the whole input dimension in one pass.
  • The epilogue applies the activation and channel scales, the bias, and the low-rank branch once, in the same kernel.

Two weight backends share that kernel. int8 stores the weights pre-expanded to int8, twice the memory of int4, and is the fastest. int4 keeps them 4-bit and expands them inside the kernel, about 16% slower in isolation. backend="auto" picks int8 when the model fits in half of the GPU's memory budget, otherwise int4. On a 24 GB Mac that means int8 for Klein 4B and int4 for Klein 9B and FLUX.1-dev. Macs without Neural Accelerators fall back to a dequantized path.

The AdaNorm modulation layers are AWQ W4A16. On MLX they map losslessly onto MLX's own 4-bit format and its built-in kernel; on PyTorch MPS they use PyTorch's int4 matmul for MPS.

Image editing

FLUX.2 Klein also edits images: the input image is encoded by the VAE and its tokens are appended to the output image's tokens, so the transformer attends to both. The same Nunchaku checkpoint loads into mflux's edit pipeline (Flux2KleinEdit) with no changes. Each edit below starts from one of the bf16 text-to-image results above, with seed 42, 4 steps and a 1024² output:

Try it

MLX

# pip install "nunchaku-lite[mlx]" mflux
import mlx.core as mx
from mflux.models.common.config.model_config import ModelConfig
from mflux.models.flux2.variants import Flux2Klein
from nunchaku_lite.mlx import load_nunchaku_pipeline

mx.set_cache_limit(1 << 30)  # keep MLX's buffer cache from pushing a 24 GB Mac into swap
model = load_nunchaku_pipeline(
    "mflux-community/flux2-klein-9b-mflux-q4",  # text encoder, VAE, scheduler
    pipeline_cls=Flux2Klein,
    checkpoint="lite-infer/flux.2-klein-9b-nunchaku-lite-int4-r32",  # only transformer/ is downloaded
    backend="auto",  # int8 or int4 from available memory
    model_config=ModelConfig.flux2_klein_9b(),
)
image = model.generate_image(seed=42, prompt="A golden retriever mid-leap catching a frisbee",
                             num_inference_steps=4, height=1024, width=1024, guidance=1.0)
image.image.save("klein9b.png")

For editing, load the same checkpoint into mflux's edit pipeline and pass the input image:

from mflux.models.flux2.variants.edit.flux2_klein_edit import Flux2KleinEdit

model = load_nunchaku_pipeline(
    "mflux-community/flux2-klein-4b-mflux-q4",
    pipeline_cls=Flux2KleinEdit,
    checkpoint="lite-infer/flux.2-klein-4b-nunchaku-lite-int4-r32",
    backend="auto",
    model_config=ModelConfig.flux2_klein_4b(),
)
image = model.generate_image(seed=42, prompt="Change the text on the cardboard sign to say JAZZ NIGHT.",
                             image_paths=["musician.png"], num_inference_steps=4, height=1024, width=1024, guidance=1.0)
image.image.save("musician_edit.png")

PyTorch MPS

# pip install "nunchaku-lite[torch]"
# pip install --no-build-isolation ./nunchaku-lite-kernels   # Metal kernels, until the Hub build is published
import torch
from diffusers import Flux2KleinPipeline
from nunchaku_lite import load_nunchaku_pipeline

repo = "lite-infer/flux.2-klein-4b-nunchaku-lite-int4-r32"
pipe = load_nunchaku_pipeline(
    repo,
    pipeline_cls=Flux2KleinPipeline,
    checkpoint=f"{repo}/transformer/diffusion_pytorch_model.safetensors",
    torch_dtype=torch.bfloat16,
    device="mps",
    backend="auto",
)
pipe.to("mps")
image = pipe("A golden retriever mid-leap catching a frisbee", num_inference_steps=4, guidance_scale=1.0).images[0]
image.save("klein4b.png")

Limitations and next steps

  • The int8 and int4 backends need an M5-class GPU (Neural Accelerators) and macOS 26. Earlier Apple GPUs use the dequantized fallback.
  • INT4 checkpoints only; NVFP4 is not supported on Apple silicon yet.
  • PyTorch MPS needs the Metal kernels built locally until the Hub build (version 3) is published.
  • MLX adapters exist for FLUX.1 and FLUX.2 Klein; other families can use the generic manifest adapter.
  • Attention is the largest remaining cost on both runtimes.
